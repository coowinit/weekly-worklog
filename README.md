# Weekly Worklog｜周度工作档案

**当前版本：** `v1.1.0`  
**项目定位：** 一款轻量、中文优先、以周为单位整理工作记录的浏览器工具。

Weekly Worklog 用于记录每周完成的工作，并保存相关备注和云文档链接。它不是日程表或复杂的项目管理系统，重点是让工作成果能够按周长期积累、查找和回顾。

## 功能

- **周度浏览：** 按年份和周次查看记录，支持上一周、下一周及返回本周。
- **星期日制周历：** 每周星期日开始、星期六结束，自动处理跨年和 52/53 周。
- **工作记录：** 新增、编辑、删除工作记录，包含日期、标题、分类、备注和多个链接。
- **分类管理：** 分类新增、编辑、删除、颜色设置和排序；删除正在使用的分类前，可将相关记录迁移到其他分类。
- **年度索引：** 按周查看全年记录数量，并跳转到指定周。
- **搜索与筛选：** 按标题、备注、链接搜索，并按工作分类筛选。
- **响应式布局：** 桌面端使用表格，手机端使用卡片。
- **数据备份：** 支持 JSON 导入和导出，记录与分类一并备份。
- **中文阅读体验：** 使用中文优先的系统字体，最小字号 12px，正文以 14px 为主。

## 快速开始

无需构建和第三方依赖。**推荐通过 VS Code Live Server 或 XAMPP 本地 HTTP 服务访问，而不是直接双击 HTML 使用 `file://`。**

1. 下载或克隆本仓库。
2. 在 VS Code 打开项目，右键 `index.html` 选择 **Open with Live Server**，通过 `http://127.0.0.1:5500/` 访问。
3. 首次打开会载入演示记录，可编辑或删除。
4. 开始录入真实工作记录前，建议先了解下方的数据保存说明。

也可以将整个目录放入 XAMPP 的 `htdocs`，通过 `http://localhost/weekly-worklog/` 访问。不同地址拥有不同的 LocalStorage，切换环境前请先导出 JSON 备份。

## 周历规则

本项目使用公历，并采用 **Sunday-start、minDays=1** 的星期日制周历规则，与 Unicode CLDR 的相应周数据配置兼容。

- 一周从**星期日**开始，到**星期六**结束。
- 包含当年 **1 月 1 日**的整周定义为该年的第 1 周。
- 跨年时，包含新年 1 月 1 日的整周归属于新的一年。
- 每年自动计算为 52 周或 53 周。
- 工作记录按记录日期归入对应周；旧记录缺少日期时，才回退使用创建时间。

这不是 ISO 8601 的周编号规则。参考：[Unicode CLDR — Dates and Week Data](https://unicode.org/reports/tr35/tr35-dates.html)。

## 数据保存与备份

当前版本是**单用户、本地浏览器版本**，使用浏览器 `localStorage` 保存工作记录和分类。

请特别注意：

- 数据保存在当前浏览器、当前访问地址对应的本地存储空间中。
- 使用不同浏览器、不同设备或不同访问地址时，数据不会自动共享。
- 清理浏览器站点数据可能导致本地记录被删除。
- 本版本不包含账号登录、云端数据库、自动云同步或多人协作。
- JSON 导出文件是当前版本推荐的备份方式。
- 导入 JSON 会替换当前浏览器中的现有记录和分类；导入前请先导出备份。

**建议定期导出 JSON，并将备份文件保存在浏览器之外的安全位置。不要把唯一一份工作记录只保存在浏览器中。**

## 数据格式与兼容性

- 浏览器本地存储键名：`weekly-worklog-v1`。
- 工作记录通过 `categoryId` 关联独立分类。
- JSON 导出包含 `records` 和 `categories`。
- 导入旧版仅包含 `records` 的 JSON 时，会使用默认分类并尝试根据旧分类名称迁移记录。
- 周历规则从 ISO 周历切换为星期日制后，历史记录会根据原始工作日期重新归档；工作记录内容和链接不会因此改变。

## 运行自动化测试

测试使用 Node.js 内置模块，不需要安装第三方测试依赖。在项目根目录运行：

```bash
node tests/calendar.test.js
node tests/storage.test.js
node tests/report.test.js
```

测试覆盖周历跨年边界、52/53 周、1900—2100 年周历计算、周次导航、非法日期，以及 JSON 和本地存储兼容性。

## 技术与浏览器要求

- 原生 HTML、CSS 和 JavaScript。
- 不依赖前端框架、第三方运行时库或构建工具。
- 中文字体优先使用操作系统已有字体，不随项目打包字体文件，也不请求远程字体服务。
- 建议使用近期版本的 Chrome、Edge、Firefox 或 Safari。

## 后续发展方向

v1.0.0 的目标是保持轻量、稳定，先作为本地浏览器工具使用。数据库接入属于未来独立阶段，目前保留两个待评估方向：

1. **WordPress 插件：** 适合希望利用 WordPress 后台、用户体系和数据库环境的场景。
2. **独立 SQLite 应用：** 适合希望保持轻量、独立部署，并使用单文件数据库的场景。

两条路线暂不预先选定，也不属于当前 v1.0.0 的功能范围。未来应先比较部署方式、备份恢复、多设备访问和维护成本，再决定是否开发。

## 设计原则

1. 以周为主要浏览和整理单位，不扩展成每日待办工具。
2. 工作记录保持简单：日期、标题、分类、备注和链接。
3. 分类用于描述工作类型，不强制引入项目管理体系。
4. 优先保证数据可导出、可备份和可迁移。
5. 不为增加功能而增加不必要的复杂度。
